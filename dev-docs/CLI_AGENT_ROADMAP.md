# Prism CLI Agent Roadmap

This document outlines the design + delivery plan for a single-CLI coding agent (codename **`prism-agent`**) that targets feature parity with Anthropic’s Claude Code CLI. The agent will live as a dedicated app inside this repo (`apps/prism-agent`) and reuse the Prism runtime + Parallax orchestration patterns for multi-agent extensions.

---

## Goals

1. **Claude Code–level UX** for “chat with your repo” plus fast tool execution (git, tests, linters, formatters).
2. **Local-first execution**: runs entirely on the developer’s machine by default, with optional Parallax backend for multi-agent upgrades.
3. **Confidence-aware workflows** using Prism semantics (uncertain if/while, confident operators) to decide when to auto-apply patches vs. escalate to the user.
4. **Composable agents** so future Parallax deployments can stitch together lint/test reviewers, doc writers, etc., without rewriting CLI UX.

---

## Feature Parity Targets (Claude Code CLI)

| Capability | Required Behaviors | Notes |
|------------|-------------------|-------|
| Conversational chat | Multi-turn prompts scoped to repo, persistent session history, quick context injection (files, diffs). | Provide `agent chat` command with `--file`, `--diff`, `--cmd-output` attachments. |
| Repo awareness | Automatic repo scan + embeddings/lists, file tree summarization, follow-up lookups. | Build `context indexer` that caches file metadata + allows `agent files search <pattern>`. |
| Tool execution | Run shell commands, tests, linters with streaming output + captured artifacts. | Provide `agent run <cmd>` / `agent test` wrappers that enforce sandbox + capture exit status/confidence. |
| Patch workflow | Generate diffs, preview, apply/rollback, open in editor. | Commands: `agent plan`, `agent apply`, `agent undo`, `agent diff`. Always ask confirmation unless confidence > threshold. |
| Task planning | Convert NL goals into step-by-step plan, track progress, rerun steps. | Prism plan orchestrations map to tasks; CLI should show plan tree similar to Claude “Tasks” view. |
| Inline explanations | Ask “Why did you change X?” or “Summarize diff”. | Reuse `agent explain <file|diff>` command. |
| Safety/Guardrails | Avoid destructive commands unless user approves; highlight low-confidence suggestions. | Prism uncertain blocks decide when to escalate. |

## High-Level Architecture

```
apps/prism-agent (new package)
├── CLI shell (Commander/Ink or existing prism CLI infra)
├── Session Manager (stores prompts, chat logs, plan state)
├── Context Indexer (file tree, embeddings hooks)
├── Tool Adapters
│   ├── Shell runner (sandboxed fork + streaming)
│   ├── Git wrapper (status, diff, apply)
│   ├── Test runner (pnpm/yarn/npm autodetect)
│   ├── Lint/format hooks
├── Prism Orchestrations
│   ├── Chat pipeline
│   ├── Plan → patch
│   ├── Confidence-based apply
│   └── Escalation to human
└── Optional Parallax Bridge
    ├── Register tool agents
    └── Replay CLI sessions as Parallax patterns
```

Key modules:

1. **`agent-core`** (shared utilities): session store, config, telemetry.
2. **`agent-context`**: repo scanning, ignore patterns, doc summaries.
3. **`agent-orchestrator`**: wraps Prism runtime to execute orchestrations (chat, plan, patch).
4. **`agent-cli`**: entrypoint exposing commands.

## Command Surface (v1 proposal)

| Command | Description |
|---------|-------------|
| `agent init` | Initialize config (LLM keys, repo name, ignore patterns). |
| `agent chat [prompt]` | Start/continue a conversation. Options: `--attach file`, `--cmd "pnpm test"`, `--model claude-3-opus`. |
| `agent plan "<goal>"` | Generate plan steps, render as checklist, store session id. |
| `agent apply <plan-id>` | Execute plan step-by-step, stream tool output, prompt user before applying patches. |
| `agent diff` | Show pending diffs generated by agent. |
| `agent undo [n]` | Revert the last `n` patches applied by agent. |
| `agent run <cmd>` | Execute arbitrary command through sandboxed runner with captured logs. |
| `agent test` | Auto-detect package manager + run tests (configurable). |
| `agent explain <file|diff>` | Summarize or justify changes. |
| `agent status` | Show active plans, confidence levels, pending escalations. |

## Implementation Phases

### Phase 0 – Research & Tooling (current)
- [x] Define feature parity targets vs. Claude Code CLI.
- [x] Document architecture + scenario mapping.
- [ ] Finalize data contracts (session logs, plan schema, telemetry events).

### Phase 1 – Local MVP
- Scaffold `apps/prism-agent` package with CLI harness + session store.
- Implement `agent chat`, `agent run`, `agent diff`, `agent apply` (preview only).
- Integrate with `@prism-lang/core` + `@prism-lang/llm` (single-provider).
- Basic repo indexing (file globbing, ignore list).
- Telemetry: stdout logging only.

### Phase 2 – Feature Parity
- Multi-provider LLM switching, streaming tokens, reasoning metadata.
- Plan execution engine (Prism orchestrations) with step tracking + resume.
- Confidence-based auto-apply (uncertain blocks).
- Tool adapters: tests, lint, format, git apply/undo.
- Enhanced context (semantic search plug-in, embeddings optional).
- Telemetry: local traces + CLI summary.

### Phase 3 – Parallax Integration
- Register tool agents inside Parallax; CLI can offload heavy tasks.
- Sync session history to Parallax control plane for collaborative review.
- Web dashboard (optional) to replay CLI sessions.
- Policy hooks (rate limiting, audit logging).

### Phase 4 – Advanced UX
- TUI dashboard (Ink) for interactive plan tracking.
- Workspace-aware knowledge base (auto doc updates).
- Plugin marketplace for custom tools (deployable via Parallax).

## Dependencies & Open Questions

- **LLM Providers**: reuse `@prism-lang/llm`; need API key management UX (env + config file).
- **Sandboxing**: initial version can shell out directly; longer term integrate with Parallax’s execution sandbox or OS-level restrictions.
- **Context Limits**: need heuristics for summarizing large repos (maybe re-use `llm-lab` embeddings later).
- **Telemetry**: evaluate hooking into existing OpenTelemetry setup vs. lightweight JSON logs.
- **Licensing**: CLI agent shipped under same MIT license; ensure third-party tool wrappers comply.
